# Clean Kitchen — Client (oshpaz ilovasi)

Restoran texnologik kartalari uchun oshpazga mo'ljallangan front-end (React + Vite + TypeScript).
`clean-kitchen v12` monoreposidagi `apps/client` dan ajratib olingan, mustaqil ishlaydi.

## Ishga tushirish

```bash
npm install
cp .env.example .env     # kerak bo'lsa VITE_API_URL ni o'zgartiring
npm run dev              # http://localhost:5173
```

Faqat demo ma'lumot bilan (serverga umuman so'rov yubormasdan):

```bash
npm run dev:mock
```

Production build: `npm run build` → `dist/`.

## Ma'lumot manbasi (server → kesh → mock)

`src/lib/api.ts` quyidagi tartibda ishlaydi:

| Holat | Nima ko'rsatiladi | Belgi |
|-------|-------------------|-------|
| Server javob berdi | Server kartalari (IndexedDB ga keshlanadi) | 🟢 «Онлайн · данные сервера» |
| Server javob bermadi (5 s timeout / xato), kesh bor | IndexedDB keshi | 🔵 «Офлайн · локальный кэш» |
| Server javob bermadi va kesh bo'sh, yoki server bo'sh ro'yxat qaytardi | **37 ta mock karta** | 🟠 «Демо-режим · 37 тестовых карт» |
| `VITE_USE_MOCK=true` | 37 ta mock karta | 🟠 |

Demo rejimida «Подключиться к серверу» tugmasi serverga qayta ulanishga urinadi.

## Интерфейс (iPhone / iPad)

Весь интерфейс на русском языке. Главная: шапка с уведомлениями, баннер-карусель, поиск (по названию и ингредиентам)
с кнопками голосового поиска и сканера QR, категории со счётчиками, недавно открытые, быстрые действия, нижняя навигация
(Главная · Поиск · Сохранённые · Категории · Меню). На iPad (≥768 px) вёрстка расширяется.

Все кнопки рабочие:

| Элемент | Что делает |
|---------|-----------|
| Микрофон | Сразу открывает экран прослушивания. Одно точное совпадение — открывается карта, несколько — список результатов |
| Сканер | Камера + jsQR; также код/ссылка вручную и фото с QR |
| Калькуляция | Себестоимость порции по всем картам, сортировка, переход в расчёт карты |
| Импорт PDF/Фото | OCR на устройстве (tesseract.js, rus+eng), PDF через pdf.js; результат сохраняется как черновик |
| QR-код карты | Генерация QR (PNG, ссылка, «Поделиться») |
| Офлайн-режим | Сохранение карт в IndexedDB, статус кэша, очистка, обновление |
| Колокольчик | Уведомления о статусе данных/сети/черновиках |

Иконки — собственный SVG-набор (`src/components/Icons.tsx`), без внешних библиотек и emoji. Тяжёлые модули (OCR, PDF, QR)
подгружаются только при открытии соответствующего экрана.

Фото блюд в mock-данных подгружаются с `loremflickr.com` по тегам блюда; если фото не загрузилось или нет сети,
показывается SVG-иллюстрация блюда (`src/components/RecipeImage.tsx`). Для карт с сервера используется `imageUrl`.
Баннеры лежат в `public/banners/`.

## Умный сканер документов (Smart Document Scanner)

Экран «Сканер документов» (кнопка сканера на главной, «Импорт (PDF/Фото)», меню): режимы **Камера / Фото / PDF / QR-код**. Документ определяется автоматически, выпрямляется, читается локальным OCR (без интернета), результат обязательно проверяется пользователем и сохраняется только после подтверждения. Подробности и правила точности — в [`docs/IMPORT_API.md`](docs/IMPORT_API.md).

**Измеренная точность (честно):** на единственном тестовом документе (технологическая карта, 11 строк × 4 числовых столбца = 44 числа) все цифры прочитаны верно (44/44), но в 6 числах «,» прочитана как «.» — они помечены жёлтым/красным, молчаливых ошибок 0. Это выборка n=1; набор из 30+ документов и замеры на реальных фото iPhone/iPad не проводились.

> Модели OCR (~14 МБ) копируются в `public/tesseract/` при `npm install`/сборке (`scripts/copy-ocr.mjs`) и не хранятся в git.

## Работа без интернета (телефон / планшет)

- **Карточки** хранятся в памяти устройства (IndexedDB). При запуске сначала показываются они (мгновенно, даже без сети), затем идёт обновление.
- **Умная синхронизация:** когда появляется интернет (или приложение возвращается из фона), клиент запрашивает у сервера `GET /api/sync/recipes?since=<время последней синхронизации>` и получает **только новое, изменённое и удалённое**. Сервер кэширует ответы в Redis.
- **Фото блюд** скачиваются на устройство и открываются без сети (если источник фото разрешает загрузку — CORS; иначе показывается встроенная иллюстрация блюда).
- **Приложение и сканер:** кнопка «Скачать всё для работы без интернета» (Меню → Офлайн-режим) сохраняет файлы приложения и модель распознавания (~15 МБ).
- Запрашивается постоянное хранилище, чтобы ОС не очищала данные при нехватке места.
- **PWA:** `manifest.webmanifest` + иконки — можно добавить на экран «Домой» (iPhone/iPad/Android). Для App Store / Google Play — Capacitor (`capacitor.config.ts`, `npx cap add ios|android`); сервер уже пропускает `capacitor://localhost` и `https://localhost`.
- В настройках сервера `VITE_API_URL` укажите адрес API (`https://…`, без `/api`).

## Голосовой поиск (точный, с отсевом шума и дальних голосов)

Как работает:
1. **Захват**: микрофон с шумоподавлением и эхоподавлением, фильтр 110–4200 Гц, 16 кГц WAV.
2. **Ближнее поле** (`src/voice/vad.ts`): считается уровень шума, берутся только сегменты речи, которые заметно громче фона (SNR ≥ 12 дБ) и не более чем на 9 дБ тише самого громкого. Далёкие голоса и шум отбрасываются, тишина/далёкая речь → «Не слышу вас…», запрос на сервер не уходит.
3. **Распознавание**: сервер (Whisper через `STT_API_KEY`, работает и в Telegram/WebView) или Web Speech/Capacitor с 5 вариантами.
4. **Подбор блюда** (`src/voice/match.ts`): фонетическое сравнение со словарём блюд, ингредиентов и тегов, устойчиво к акценту и ошибкам произношения. Уверенное совпадение открывает карточку, неуверенное — «Вы имели в виду…».

Проверка: `npm run test:voice` (синтетические сигналы + набор искажённых фраз).

Честные ограничения: тесты на синтетических данных и написанных вручную вариантах, не на живой речи с акцентами. Отсев дальних голосов основан на громкости, поэтому очень громкий далёкий голос или тихий ближний могут быть оценены неверно. Без `STT_API_KEY` на сервере голос в iOS/Telegram WebView не работает. Задайте `VITE_API_URL` на хостинге клиента.

## Единое приложение: вход, роли, рестораны (v13)

Один клиент для всех: после входа сервер (`/api/v1/auth`) возвращает роль, ресторан и разрешения, и из них динамически строятся меню и экраны.

- **Super Admin** → экран «Платформа»: рестораны (создание с владельцем, блокировка/активация/архив, смена владельца, read-only просмотр с записью в журнал), пользователи, системный Audit Log.
- **Владелец / Управляющий / Шеф** → обычное приложение + раздел «Меню → Управление»: панель, технологические карты (создание, правка, публикация, архив, копия, удаление), категории, ингредиенты, сотрудники (роль, категории, цеха, срок доступа, блокировка, отзыв сессий), роли с матрицей прав, калькуляции, журнал. Вкладки показываются только при наличии прав.
- **Повар / своя роль** → видит только назначенные карты; голос, QR, озвучка, сканер и себестоимость — только если разрешены ролью.
- **Безопасность на клиенте**: access-токен только в памяти (не в localStorage), refresh — HttpOnly-cookie; при выходе и смене ресторана данные на устройстве (IndexedDB, черновики) стираются. Скрытие кнопок — лишь удобство, сервер перепроверяет каждое действие.
- **Демо без входа** (общий каталог) включено по умолчанию; для продакшена задайте `VITE_ALLOW_GUEST=false`.
- Переменные: `VITE_API_URL` — адрес backend.

Ограничения: управление картами в интерфейсе — форма без загрузки фото; загрузка изображений и экспорт файлов в UI пока нет (есть в API: `/recipes/export`).
